# GBA 宝可梦本地化核心架构与技术规范 (Technical Reference)

## 1. GBA 宝可梦文本系统原理

在基于 `pokeemerald` 和 `pokeemerald-expansion` 的现代 C 语言反编译工程中，文本系统与传统商业 ROM 的主要区别如下：

### 1.1 字符映射 (`charmap.txt`) 与字模 (.latfont / .hwjpnfont)
- **单字节字符**：原版英美版仅支持 `0x00~0xFF` 的单字节编码，汉字无法直接容纳。
- **双字节汉字支持**：
  - 汉字编码采用 `0x0100 ~ 0x1E00` 双字节空间；
  - 高位字节判断逻辑：`currChar >= 0x01 && currChar <= 0x1E && currChar != 0x06 && currChar != 0x1B`；
  - 低位字节：`nextChar <= 0xF6`；
  - 字模采用点阵字体生成器，将 `.png` 位图字体转化为游戏只读数据存储段（`.latfont`）。
- **保留宏定义与冲突排查**：
  - 各个大型改版（如心魂）常在 `charmap.txt` 中扩充自研战斗宏（例如 `B_RIVAL_NAME = FD 48`，`POKE = 55 56`）。
  - 导入中文字库映射表时，**绝对不可直接整文件覆盖**，必须做差异比对并保留目标项目的特有宏。

## 2. 文本控制代码与排版约束 (Control Codes)

GBA 屏幕分辨率为 **240 × 160 像素**，标准对话框高度为 **两行文字**。

| 控制符 | 汇编语法 | 功能说明 | 排版规则 |
|---|---|---|---|
| `\p` | `\p` | 分页/按键清屏 | 清空当前对话框，等待玩家按 A 键后显示下一框。 |
| `\n` | `\n` | 换行 | 移动到对话框的第二行。每框只能有一次 `\n`。 |
| `\l` | `\l` | 滚行 | 第一行文字向上滚动顶出，第二行滚为第一行，当前行变为新行。 |
| `$` | `$` | 字符串结束符 | 每一个对白文本末尾必须携带，不可遗漏。 |

### 宽度约束：
- **大字体（标准对话框，`FONT_NORMAL`）**：
  - 汉字全角宽度一般为 12 像素，单行容纳上限为 **16~18 个汉字**。
  - 第一行用 `\n`，后续滚动使用 `\l`，段落结束换框使用 `\p`。
- **小字体（道具描述、技能说明等，`FONT_SMALL`）**：
  - 建议单行容纳不超过 **20 个汉字**。

## 3. 常见陷阱与调试经验 (Troubleshooting & Hard Lessons)

### 3.1 预处理器条件编译冲突 (`#if / #else / #endif`)
- **陷阱**：在某些脚本（如 `data/text/battle_tent.inc`、`event_ticket_1.inc`）中，同一个 Label 下会使用 `#if IS_HNS ... #else` 提供两套不同地区的对白。
- **后果**：如果抽取器与回填器不具备预处理器感知能力，两套不同分支会被当成同一条对白反复覆写，导致编译出错误的剧情分支。
- **规范**：遇到预处理器指令行时，必须立即作为逻辑分块边界截断。

### 3.2 变量占位符等价性防护
- 源代码中包含丰富的运行时动态变量：
  - `{PLAYER}`：主角姓名
  - `{RIVAL}`：劲敌姓名
  - `{STR_VAR_1}` ~ `{STR_VAR_3}`：系统临时插值字符串（道具、技能、宝可梦名）
  - `{KUN}`：日语称谓敬称占位符
  - `{COLOR ...}` / `{HIGHLIGHT ...}`：文本高亮颜色切换
- **铁律**：翻译后的译文必须通过集合比对 `set(source_vars) == set(translation_vars)`，任何占位符的增删或大小写变更都会导致游戏引擎内存越界。

### 3.3 物理换行符污染
- 大模型或 JSON 序列化时容易将换行输出为物理字节 `\x0A`。
- 必须通过 Linter 统一标准化为显式的转义字符 `\n`、`\l`，避免 C 编译器报 `unterminated string literal`。
